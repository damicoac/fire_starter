Platform Features

Built for local, inspectable assessments

Fire Starter keeps orchestration, session context, evidence, and persistence inside your environment so you can validate what happened and why.

Self-hosted runtime

Build and run the agent locally with Go. Use hosted model providers (OpenAI, Anthropic, Gemini) or point -provider local at an OpenAI-compatible endpoint while keeping scanning local.

Vulnerability Lifecycle & Confidence

Track findings through explicit lifecycle states (candidate, confirmed, informational, disproven) with separate severity scoring (critical to low) and confidence validation.

Session & Cookie Jar Management

Automatic cookie jar tracking and bearer token extraction allow seamless session propagation across main agent workflows and focused helper sub-agents with auth retry throttling.

Dual-Pane TUI & SQLite Persistence

Interactive Bubble Tea TUI with log category filters (All, Errors, Agent, Modules, System), knowledge graph inspector, and durable SQLite storage in fire_starter.db.

Autonomous Workflow

A phase-aware assessment loop

The agent scores available tools per target, updates the knowledge graph after execution, and advances through the engagement based on verified evidence.

1. Reconnaissance

Bootstraps target knowledge through discovery-oriented techniques such as search, subdomain work, and initial surface mapping.

2. Scanning & Surface Mapping

Expands context with route checks, port discovery, component version analysis, and security header checks to identify reachable attack surfaces.

3. Vulnerability Analysis & Candidate Scoring

Probes likely weaknesses (JWT, mass assignment, SQLi, BOLA), records initial signals as candidate findings, and enriches session state.

4. Helper Verification & Exploitation

Spawns focused helper sub-agents to validate candidates, capturing proof-of-concept evidence and promoting findings to confirmed or informational status.

5. Reporting & Knowledge Graph Dump

Generates fire_starter_report.md with confirmed findings and severity metrics while storing full execution records in fire_starter.db.

Built-in Coverage

Broad default technique set

The repository ships with a large set of built-in Go modules across reconnaissance, analysis, exploitation, and post-exploitation workflows.

Authorization and logic

  • BOLA, BFLA, and IDOR validation paths
  • Mass assignment and business-logic bypass checks
  • Rate-limit probing & assessment confidence modules

Web and API input abuse

  • SQL, NoSQL, XPath, LDAP, and command injection modules
  • GraphQL introspection and schema security checks
  • HTTP verb tampering, smuggling, and parameter pollution

Session, JWT & header security

  • JWT audit (alg: none, key confusion, kid header manipulation)
  • Cookie Jar session management & auth token propagation
  • CORS, security headers, and cookie attribute analysis

Discovery and infrastructure

  • Google dorking, subdomain enumeration, and takeover analysis
  • Port scanning, component version analysis, and route discovery
  • Local privilege escalation and SSH pivot modules

Under the Hood

Designed around registries and shared state

The CLI entrypoint, orchestration workflow, module registry, executor, knowledge graph, SQLite persistence, and TUI are cleanly separated so contributors can extend one layer effortlessly.

Factory registration pattern
func init() {
    RegisterModule("my_module", func(payload map[string]any, onLog func(string)) (ExecutableModule, error) {
        target := PayloadString(payload, "url", "http://127.0.0.1")
        module := &MyModule{Target: target}
        return ModuleWrapper{
            Module: module,
            ExecuteFunc: func(ctx context.Context) (any, error) {
                return module.Execute(ctx)
            },
        }, nil
    })
}

Architecture overview

Flags and config are loaded in cmd/fire_starter/main.go. The agent workflow in src/agent/workflow.go initializes the provider, scores tools, manages target progression, and drives helper sub-agents. The executor in src/matrix/real_executor.go resolves techniques to registered module factories under src/modules/core, while src/matrix/knowledge_graph.go and src/matrix/db.go retain evidence and manage vulnerability lifecycles in fire_starter.db.

Adding a new built-in check

Current runtime support is centered on the built-in registry in src/modules/core.

1
Define the technique Add metadata in src/matrix/decisions.json.
2
Implement the module Create the Go implementation in src/modules/core/.
3
Register and test Register it with RegisterModule and add _test.go coverage.

Build, inspect, and extend

Clone the repository, run the CLI locally, review the docs, and extend the built-in registry when you need new assessment techniques.
